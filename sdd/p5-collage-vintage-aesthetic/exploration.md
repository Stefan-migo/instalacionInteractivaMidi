# Exploration: p5-collage-vintage-aesthetic

## Current State

Our p5-collage is a grid-based overlapping collage system driven by phone-slot interaction:

- **Layout**: Fixed grid (5 rows × 6 cols) generated by `scripts/generate-layout.js` with per-cell random offsets, z-indices, and rotations. Cells have pixel coordinates absolute on the 1920×1080 canvas.
- **Adaptive Layout**: `adaptive-layout.js` recomputes positions when phones connect/disconnect, using grid heuristics (2×1, 2×2, 3×2, etc.) with overlap and margin.
- **Rendering**: Pure p5.js — `drawImg()` handles flip/opacity, `generateTornBorder()` creates procedural LCG-based torn edges, `TransitionRenderer` handles crossfades.
- **Controls**: Phone-slot actions via WebSocket (cycle images, flip, opacity, shuffle, lock).
- **Background**: Solid dark (`#0a0a0a`), no texture or noise.
- **Filters**: None — raw images drawn on canvas.
- **Border Styles**: Only torn (generated via LCG algorithm).
- **Blend Modes**: Supported via `blend-mode-next`/`prev` actions (5 modes).

## TempExample Reference

The `tempExample/p5-vintage-collage-studio/` is a React + p5.js webapp with:

- **Layout**: 6 presets computed as percentage-based (0-100%) positions with per-item rotation, scale, opacity.
- **Torn Edges**: CSS `clipPath` polygons (6 predefined shapes), not procedural.
- **Filters**: CSS `filter` strings per image — sepia, grayscale, cyanotype, polaroid, vintage, none.
- **Borders**: 5 styles — torn, polaroid, stamp, gold, minimal — all CSS/HTML.
- **Background**: p5 canvas renders noise fibers + dust particles; CSS layers add grid/radial gradient textures.
- **Blend Modes**: CSS `mix-blend-mode` (7 modes).
- **Z-index**: Bring-to-front via max z+1.
- **Drag/Rotate**: Interactive mouse/touch drag, rotation buttons, scale slider.

## Research Goals

### 1. Positioning (Percentage-based x, y, rotation, scale)

| Aspect | TempExample | Our Project |
|--------|------------|-------------|
| Units | `%` (0-100 of container) | Pixels (absolute on 1920×1080) |
| Transform | `translate(-50%, -50%) rotate(Rdeg)` | Direct x,y + rotation in draw |
| Scale | Multiplies natural `width`/`height` | Cell `w`/`h` from layout.json |
| Rotation | Full -180 to 180° via CSS | -6 to 6° deterministic slot hash |

**Adaptation**: Percentage-based positions are more flexible for variable-sized displays. However, our 1920×1080 fixed canvas means pixel coords work fine. The key upgrade is adding per-cell `scale` and wider rotation range.

### 2. Torn Paper Edges

| Aspect | TempExample | Our Project |
|--------|------------|-------------|
| Implementation | CSS `clipPath: polygon(...)` | p5.js `vertex()` LCG noise |
| Variants | 6 predefined shapes | Deterministic per seed (unlimited) |
| Rendering | CSS crop + white base scaled 1.045× | Outline stroke + clipping |
| Quality | Good (hand-crafted) | Good (procedural, looks organic) |
| Performance | GPU-accelerated (CSS) | CPU (per-frame shape drawing) |

**Adaptation**: Our LCG algorithm is actually superior — it's deterministic per slot, produces unique edges, and doesn't require predefined polygons. **Keep our approach** for torn edges, but we could add the 5 border styles from the tempExample rendered in p5.

### 3. Filters (per-image CSS filters)

**TempExample** uses CSS `filter` with per-preset strings:

| Filter | CSS |
|--------|-----|
| `sepia` | `sepia(0.85) contrast(1.1)` |
| `grayscale` | `grayscale(1.0) contrast(1.3)` |
| `cyanotype` | `sepia(0.4) saturate(1.9) hue-rotate(180deg) brightness(0.85) contrast(1.2)` |
| `polaroid` | `contrast(1.2) saturate(0.6) brightness(1.15) sepia(0.1)` |
| `vintage` | `sepia(0.35) saturate(0.7) contrast(0.95) brightness(1.03)` |
| `none` | (empty) |

Plus per-item `brightness`, `contrast`, `hueRotate`.

**Our project**: No filters. Images are drawn raw via `drawingContext.drawImage()`.

**Adaptation**: We can apply filters using p5.js `filter()` or raw Canvas 2D context filters. The cleanest approach is to draw images to an offscreen canvas, apply the filter, then draw to main canvas. Or use the newer `canvas.context.filter` property which accepts CSS filter strings — supported in all modern browsers.

### 4. Z-index

| Aspect | TempExample | Our Project |
|--------|------------|-------------|
| Mechanism | CSS `zIndex` property | Slot-based zIndex sorted in draw loop |
| Bring-to-front | Sets `zIndex = maxZ + 1` | Not implemented in current code |
| Drawing order | Implicit (higher z renders on top) | Explicit sort of `activeSlots` by zIndex |

**Adaptation**: We already control draw order in `drawGrid()`. Adding a bring-to-front action (triggered by phone) is straightforward — set `s.pos.zIndex = maxZ + 1`.

### 5. Layout Presets (6)

| Preset | Algorithm | Characteristics |
|--------|-----------|-----------------|
| `scatter` | Uniform random 12-88% | Full frame coverage, wide rotation |
| `spiral` | Angle * 0.45 + radius growth | Radiating outward from center |
| `polaroid-stack` | Tight center (30-70%) | Messy pile, high overlap |
| `neat-grid` | 5×6 with random ±2 offset | Organized but organic |
| `vignette` | Border placement (30-44 dist) | Center open, edges filled |
| `random` | Full chaos 5-95% | Maximum entropy |

**Adaptation**: These can be adapted as coordinate generators for our slot system. Each phone connect would either:
- (a) Recompute all positions when slots change (like adaptive layout does now)
- (b) Assign positions on connect and cache them

Option (a) is simpler and matches current architecture.

### 6. Blend Modes

| Aspect | TempExample | Our Project |
|--------|------------|-------------|
| Modes | `normal`, `multiply`, `screen`, `overlay`, `darken`, `luminosity`, `difference` | `source-over`, `multiply`, `screen`, `overlay`, `difference` |
| Implementation | CSS `mix-blend-mode` | p5 `blendMode()` — set per cell before drawing |

**Adaptation**: Our current implementation already supports blend modes via `blend-mode-next`/`prev`. We need to apply `blendMode()` before each cell draw. Note that `luminosity` and `darken` are available in Canvas2D but not in p5's wrapper — we may need to use `drawingContext.globalCompositeOperation` directly.

### 7. Background Texture (p5 canvas noise)

**TempExample** renders on a transparent p5 canvas overlaid on the workspace:
- **Fibers**: Random short lines (`line()`) drawn with persistent seed, intensity controlled
- **Dust**: Small ellipses (`ellipse()`) with noise intensity
- **CSS layers**: Radial gradients, grid patterns, color overlays
- **4 Background Styles**: aged-paper (warm amber), canvas (linen), wood (dark brown), dark-wool (charcoal)

**Our project**: Solid `#0a0a0a` background via `background()` call.

**Adaptation**: We can implement a background texture layer drawn first in the draw loop. Options:
- Draw noise/dust with p5 primitives (flexible, CPU cost)
- Use a pre-rendered texture canvas (cache noise, draw once)
- Use CSS backgrounds on the canvas element (simplest, but must match scaling)

### 8. Border Styles (5)

| Style | TempExample Implementation | p5 Adaptation |
|-------|---------------------------|---------------|
| `torn` | CSS clipPath polygons | LCG algorithm (already done, keep) |
| `polaroid` | White border + corner triangles + caption | Draw white rect underneath + small triangles at corners |
| `stamp` | Dashed border + perforation holes + badge | Draw border + circle array along edges + text badge |
| `gold` | Thick gold frame + inner border + corner rivets | Draw gold rect + thin inner rect + tiny circles at corners |
| `minimal` | Clean 2px border + white background | Simple rect border |

**Adaptation**: All 5 can be rendered in p5 Canvas2D — no CSS needed. The cell-renderer already has `drawTornBorder()`; we can add a `drawBorder(style, ...)` dispatch.

## Approaches

### Approach A: Minimal Vintage — Filters + Background Only

Add per-image CSS-style Canvas filters and background noise/dust texture. Keep existing grid layout and single torn border style.

- **Pros**: Minimal changes, preserves existing architecture entirely, quick win
- **Cons**: No free-form overlapping feel, no layout presets, no border variety
- **Effort**: Low (2-3 files, ~100 lines)

### Approach B: Full Free-Form Overhaul

Replace adaptive-layout with the 6 preset system. Add all 5 border styles rendered in p5. Add filters, background texture, and per-cell scale/rotation controls.

- **Pros**: Complete vintage aesthetic, most visually impressive
- **Cons**: Major refactor of layout system, potential disruption to phone-slot workflow
- **Effort**: High (6+ files, ~500 lines)

### Approach C: Hybrid — Preset Layout Mode + Filters + Borders

Keep adaptive layout as one "live" mode. Add a `free-form` mode that computes positions using preset algorithms. Add filters, 5 border styles, and background texture. Phone slot assignment picks a free-form position from the preset pool.

- **Pros**: Best of both worlds — retains adaptive layout for demos, adds free-form for visual impact
- **Cons**: Two layout modes to maintain, more code
- **Effort**: Medium (5-6 files, ~350 lines)

## Recommendation

**Approach C (Hybrid)** — but with a twist: instead of two modes, **replace adaptive-layout entirely with the preset system**, computed dynamically when slot counts change. This actually simplifies the architecture:

1. On phone connect/disconnect → recompute all slot positions using selected preset.
2. Each slot gets percentage-based x, y, rotation, scale, filter, border style.
3. Existing phone actions (cycle, flip, opacity) control visual toggles, not layout.
4. New phone action `set-layout` cycles through presets.

This way we get the free-form overlapping feel without maintaining two layout engines. The presets handle 1-30 items gracefully because they're computed per-item regardless of count.

**Key adaptation decisions:**
- Keep **LCG torn border** (our implementation is stronger than CSS polygons)
- Add 4 more border styles rendered in Canvas2D (`polaroid`, `stamp`, `gold`, `minimal`)
- Apply filters via `drawingContext.filter` (CSS filter strings pass-through)
- Background texture: dedicated p5 layer drawn first (noise + dust)
- All presets generate **pixel coordinates** (we're fixed at 1920×1080) — convert percentage by `x = perc/100 * canvasW`

## Risks

- **Performance**: Background noise + 5 border styles + filters + blend modes per cell may drop frame rate on low-end devices. Mitigation: pre-render noise to offscreen canvas, cache static elements.
- **Bridge protocol**: New actions (set-layout, set-filter, set-border) must be added to both phone-client and bridge. Existing protocol must remain backward-compatible.
- **Layout regeneration**: If presets change positions on every connect, phones may see their image jump. Solution: cache positions on assignment, only recompute on explicit layout change action.
- **Filter quality**: Canvas `context.filter` may differ slightly from CSS `filter` in some browsers. Test on Chrome/Firefox/Safari targeting the installation setup.
- **Image aspect ratio**: TempExample uses fixed w/h per image. Our images are historical with varying aspect ratios — need aspect-ratio-aware scale computation.
